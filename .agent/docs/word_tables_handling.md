# التعامل مع جداول الوورد (Word Tables) في مشروع Golden Shamela

## مقدمة
تعتبر الجداول (`w:tbl`) من أعقد العناصر في بنية ملفات الوورد (Open XML)، حيث تتطلب معالجة خاصة لتحويلها من تنسيق يعتمد على قياسات الطباعة (Twips) إلى تنسيق مرن (Widgets) داخل بيئة Flutter. هذا المستند يشرح بالتفصيل الممل الخوارزميات المستخدمة في الكلاس `ParagraphTable.dart` وكيفية معالجة الأبعاد (الطول والعرض) والمشاكل الشائعة وحلولها.

---

## 1. بنية الجدول في XML
كل جدول في ملف `document.xml` يبدأ بالوسم `<w:tbl>` ويحتوي على ثلاثة أقسام رئيسية:
1.  **خصائص الجدول (`w:tblPr`)**: تحتوي على إعدادات عامة مثل العرض الكلي، المحاذاة، والحدود.
2.  **شبكة الجدول (`w:tblGrid`)**: تعرف الأعمدة الأساسية وعرض كل عمود قبل دمج الخلايا.
3.  **محتوى الجدول (الصفوف `w:tr`)**: وكل صف يحتوي على خلايا (`w:tc`).

```xml
<w:tbl>
  <w:tblPr>
    <w:tblW w:w="5000" w:type="pct"/> <!-- العرض كنسبة مئوية -->
  </w:tblPr>
  <w:tblGrid>
    <w:gridCol w:w="2000"/>
  </w:tblGrid>
  <w:tr>
    <w:tc>...</w:tc>
  </w:tr>
</w:tbl>
```

## 2. خوارزمية حساب عرض الجدول (Table Width)

حساب عرض الجدول يمر بمراحل معقدة لضمان ظهوره بشكل صحيح على شاشات الهواتف التي تختلف تماماً عن صفحات A4.

### أ. الوحدات المستخدمة
*   **Twips**: وحدة قياس الوورد (1/1440 من الإنش).
*   **Pixels**: وحدة العرض في الشاشة.
*   **معامل التحويل (Scaling Factor)**: نستخدم المعامل `0.0667` لتحويل Twips إلى Pixels تقريبياً.

### ب. خطوات الحساب (كما في `ParagraphTable.dart`)

**الخطوة 1: حساب العرض الطبيعي (Natural Width)**
يقوم النظام بجمع جميع عروض الأعمدة المعرفة في `w:tblGrid`. إذا لم تكن الشبكة موجودة، يحاول جمع عروض الخلايا `w:tcW` من الصف الأول كبديل.
> `totalGridTwips = Sum(gridColWidths)`

**الخطوة 2: التحقق من العرض المحدد (`w:tblW`)**
هذه خطوة حاسمة تمت إضافتها مؤخراً. الوورد قد يحدد عرض الجدول بطريقتين:
1.  **قيم ثابتة (`dxa`)**: رقم محدد بالـ Twips.
2.  **نسبة مئوية (`pct`)**: وهنا تكمن الصعوبة. القيمة `5000` تعني 100%.

**آلية حساب النسبة المئوية:**
لتحويل النسبة المئوية إلى بكسلات فعلية، نحتاج لمعرفة "عرض الصفحة المتاح". يتم ذلك عبر الكلاس `SectPr`:
1.  نجلب `SectPr.width` (عرض الصفحة الكلي).
2.  نطرح منه الهوامش (`leftMargin` + `rightMargin`).
3.  النتيجة هي `pageBodyWidth`.
4.  العرض المستهدف = `pageBodyWidth * (Percent / 5000)`.

**الخطوة 3: تحديد معامل القياس النهائي (Scale Factor)**
بعد تحديد العرض المستهدف بالبكسل (`targetWidthPx`)، نقارنه بعرض الشاشة الحالي (`screenWidth`):
*   إذا كان الجدول أصغر من الشاشة، نستخدمه كما هو.
*   إذا كان أكبر من الشاشة، نقوم بتقليصه ليناسب الشاشة، ونحسب `scaleFactor` جديد لضغط المحتوى.

> **القاعدة الذهبية:** الأولوية دائماً لـ `w:tblW` (النسبة المئوية) لأنها تعبر عن نية المصمم في الوورد بأن يشغل الجدول مساحة محددة من الصفحة، بغض النظر عن محتواه الداخلي.

## 3. خوارزمية حساب ارتفاع الصفوف (Row Height)

ارتفاع الصف (`Row Height`) أكثر تعقيداً لأنه يتأثر بعاملين: إعدادات الصف نفسه، ومحتوى الخلايا بداخله.

### أ. إعدادات الصف (`w:trPr`)
كل صف قد يحتوي على وسم `<w:trHeight>` وله خاصيتان:
1.  **`val`**: القيمة الرقمية للارتفاع.
2.  **`hRule`**: قاعدة تطبيق الارتفاع:
    *   **auto**: الارتفاع يتمدد حسب المحتوى (الافتراضي).
    *   **atLeast**: الارتفاع لا يقل عن القيمة المحددة، لكن يمكن أن يزيد.
    *   **exact**: ارتفاع ثابت صارم، ويتم قص المحتوى الزائد.

في التطبيق، نترجم هذه القواعد كالتالي:
*   `exact` -> نستخدم `SizedBox(height: ...)` لإجبار الارتفاع.
*   `atLeast` -> نستخدم `ConstrainedBox(minHeight: ...)` للسماح بالتمدد.

### ب. مشاكل الارتفاع الزائد وحلولها
واجهنا مشكلة شائعة حيث تظهر الصفوف بارتفاع مضاعف مقارنة بالوورد. تبين أن الأسباب خفية وتقنية جداً:

#### 1. المسافات الافتراضية للفقرات (`Spacing`)
في الوورد، الفقرات العادية (`Normal Style`) لها مسافة سفلية (Spacing After) تقدر بـ 10pt.
*   **المشكلة:** عند وضع نص داخل جدول، الوورد عادة يلغي هذه المسافة، لكن الكود الخاص بنا كان يطبقها لأنها القيمة الافتراضية للفقرة.
*   **الحل البرمجي:** في دالة `getCellWidget`:
    ```dart
    // إذا لم يكن هناك تباعد صريح في XML
    if (!hasExplicitSpacing) {
       // نجبر المسافات على الصفر
       paragraph.pPr!.spacingBefore = 0;
       paragraph.pPr!.spacingAfter = 0;
    }
    ```

#### 2. الفواصل المخفية (`Trailing Line Breaks`)
هذه كانت المشكلة الأصعب. بعض الجداول تحتوي في نهاية الخلية على كود XML بهذا الشكل:
`<w:r><w:br/><w:t> </w:t></w:r>`
*   **التفسير:** يوجد "نزول سطر" (`br`) متبوع بمسافة فارغة.
*   **سلوك الوورد:** يتجاهل هذا السطر الأخير غالباً في حساب ارتفاع الخلية إذا كان فارغاً.
*   **سلوك التطبيق:** كان يرسمه كسطر جديد حقيقي، مما يضيف ارتفاعاً إضافياً لكل صف.
*   **الحل البرمجي (The Cleanup Algorithm):**
    تمت إضافة خوارزمية تنظيف ذكية تقوم بالآتي:
    1.  تفحص مكونات الفقرة (`runs`) من النهاية إلى البداية.
    2.  إذا وجدت مكوناً يحتوي على فاصل سطر (`hasBr`) وكان النص فيه فارغاً أو مسافة بيضاء فقط.
    3.  تقوم بإلغاء هذا الفاصل (`run.hasBrAfter = false`).
    4.  **تحديث هام:** تمت إضافة منطق لتجاهل النصوص "المخفية" أو الصغيرة جداً (حجم خط <= 2pt) التي قد تستخدم كعلامات مرجعية، حتى لا تمنع الخوارزمية من الوصول للفاصل السطر الزائد وحذفه.

## 4. معالجة محتوى الخلايا (Cell Content)

معالجة النصوص داخل الخلية تختلف عن النص العادي في الصفحة بعدة نقاط:

### أ. الهوامش الداخلية (`Padding`)
الخلية في الوورد لها هوامش داخلية (`w:tcMar`). في التطبيق، قمنا بتبسيط ذلك لتقليل التعقيد:
*   نستخدم `EdgeInsets.symmetric(horizontal: 1, vertical: 0)` بشكل افتراضي.
*   تم إلغاء التباعد العمودي (`vertical: 0`) لضمان عدم إضافة أي مساحات غير ضرورية، والاعتماد كلياً على ارتفاع الخط (`Line Height`) ومسافات الفقرات.

### ب. اتجاه النص والمحاذاة
*   **`w:jc` (Justify):** المحاذاة داخل الخلية.
*   **`w:textDirection`:** الجداول قد تحتوي على نص عمودي. يتم التعامل معه باستخدام `RotatedBox` لتدوير المحتوى 90 أو 270 درجة حسب المطلوب (`tbRl` أو `btLr`).

## 5. الحدود والتظليل (Borders & Shading)

رسم حدود الجدول ليس بالأمر السهل لأن الحدود يمكن تعريفها في ثلاثة أماكن مختلفة، ويجب تطبيق مبدأ "الأولوية" (Precedence):

1.  **الحدود المباشرة للخلية (`w:tcBorders`)**: لها الأولوية القصوى.
2.  **الحدود العامة للجدول (`w:tblBorders`)**: تطبق إذا لم يكن للخلية حدود خاصة.
3.  **حدود الستايل (`Table Style`)**: تطبق إذا لم يوجد تعريف مباشر.

خوارزمية `_getCellBorder` في الكود تقوم بهذا الترتيب وتدمج النتائج لإنتاج كائن `BoxDecoration` لـ Flutter.

## 6. ملخص الخوارزميات (Technical Summary)

### خوارزمية تنظيف الارتفاع (Height Cleanup Logic)
```dart
Loop Backwards through Runs:
  Let Run = Current Run
  Let Size = Run.FontSize OR Default(10pt)
  
  IF (Text is Empty OR Whitespace Only) OR (Size <= 2pt):
     // هذا العنصر لا يعتبر محتوى حقيقياً يمنع الحذف
     Remove Run.BrAfter
     Remove Run.BrBefore
     Continue Loop (ابحث في العنصر السابق)
  ELSE:
     // وصلنا لمحتوى حقيقي
     Remove Run.BrAfter (احذف الفاصل الملاصق له فقط)
     BREAK (توقف، لا تحذف فواصل داخل النص)
```

### خوارزمية حساب العرض (Width Logic)
```dart
IF (w:tblW type == 'pct'):
   Target = PageWidth * (Value / 5000)
ELSE IF (w:tblW type == 'dxa'):
   Target = Value * ConversionFactor
ELSE:
   Target = Sum(GridCols)

FinalWidth = Min(Target, ScreenWidth)
ScaleFactor = FinalWidth / Sum(GridCols)
```
