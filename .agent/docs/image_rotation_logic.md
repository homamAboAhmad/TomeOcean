# توثيق آلية تدوير وقلب الصور (Image Rotation & Flipping Logic)

## 1. المقدمة والمشكلة
يواجه عرض الصور من ملفات Word (`.docx`) تحدياً كبيراً عند التعامل مع الصور التي التقطت بكاميرات الهاتف (التي تحتوي على بيانات EXIF للاستدارة) والتي تم تدويرها أيضاً داخل برنامج Word.

### المشكلة الأساسية: "الدوران المزدوج" (Double Rotation)
1. **EXIF:** الصورة الأصلية قد تكون "عمودية" (Portrait) ولكن بيانات الكاميرا تقول "دّورني 90 درجة". مكتبات Flutter الحديثة (مثل `Image.memory`) تقرأ هذه البيانات وتصحح الصورة تلقائياً لتظهر عمودية.
2. **XML:** برنامج Word يقوم بتدوير الصورة أيضاً (مثلاً 270 درجة) لتظهر أفقية.
3. **النتيجة:** إذا طبقنا دوران XML (270) فوق تصحيح EXIF التلقائي، قد تنقلب الصورة مرتين أو تظهر باتجاه خاطئ.

---

## 2. آلية اتخاذ القرار (The Logic)

يتم اتخاذ القرار في ملف `lib/Utils/ImageParser.dart` في الدالة `setRotation`.

### أ. تحليل الدوران والانعكاس (Rotation & Flip Parsing)
نقرأ السمات من عنصر `<a:xfrm>` في ملف XML:
- `rot`: قيمة الدوران بوحدة 1/60000 درجة.
- `flipH`: قلب أفقي (`1` أو `true`).
- `flipV`: قلب عمودي (`1` أو `true`).

### ب. معضلة الأبعاد (The Dimensions Dilemma)
عند دوران الصورة 90 أو 270 درجة، يجب منطقياً "تبديل" العرض والارتفاع (`Swap Width/Height`) لكي يكون "صندوق" الصورة (Container) متناسباً مع المحتوى الجديد.
*   **مثال:** صورة 200x100 (أفقية) دُوّرت 90 درجة -> يجب أن تحجز مساحة 100x200 (عمودية).

### ج. الكشف عن التعارض (Conflict Detection & Heuristic)
كيف نعرف متى نطبق الدوران ومتى نتجاهله؟ الحل يكمن في مراقبة عنصر `effectExtent` (تأثيرات إضافية مثل الظل أو الانعكاس).

**الملاحظة الحاسمة:**
وجدنا نمطاً متكرراً في ملفات المستخدم:
- الصور التي تظهر بشكل خاطئ (تحتاج إصلاح) غالباً ما تحتوي على `effectExtent` (بسبب معالجة Word لها).
- هذه الصور تكون بياناتها الأصلية (EXIF) سليمة أفقياً، ولكن Word يضيف عليها دوران 270 درجة في XML.

**خوارزمية الحل (The Fix Algorithm):**

1. **حساب التوافق (Aspect Ratio Check):**
   - هل نسبة أبعاد الصورة (`extent`) تختلف عن نسبة التحويل (`xfrm`)؟
   - إذا كان الاختلاف كبيراً، فهذا مؤشر قوي على أن الأبعاد تحتاج للتبديل.

2. **شرط المبادلة (Swap Logic):**
   إذا كان الدوران 90 أو 270 درجة **و** نسب الأبعاد غير متطابقة:
   -> **نقوم بتبديل العرض والارتفاع (`_imageData.width` <-> `_imageData.height`).**
   هذا يضمن أن الصندوق الحاوي للصورة يأخذ الشكل الصحيح (Landscape/Portrait).

3. **شرط تصفير الدوران (Rotation Suppression):**
   هنا يكمن السحر. بعد تبديل الأبعاد، نسأل: هل يوجد `effectExtent`؟
   - **نعم (True):** (الحالة المعقدة)
     - هذا يعني غالباً أن الصورة عولجت في Word وهي تعاني من تعارض EXIF/XML.
     - **الإجراء:** نصفر الدوران (`rotation = 0`).
     - **السبب:** لأننا بدلنا الأبعاد، أصبح الصندوق أفقياً. والصورة بفضل EXIF هي أصلاً أفقية. لذا لا نريد دوران XML الإضافي الذي سيفسدها.
   - **لا (False):** (الحالة الطبيعية)
     - نبقي الدوران كما هو (نطبق دوران XML).

## 3. التنفيذ البرمجي (Implementation Details)

### في `ImageParser.dart`:
```dart
if (arMatches) {
  // 1. Swap Dimensions (For Layout)
  double temp = _imageData.width;
  _imageData.width = _imageData.height;
  _imageData.height = temp;
  
  // 2. Suppress Rotation (For Rendering Content)
  if (hasEffectCompensation) {
    _imageData.rotation = 0;
  }
}
```

### في `ImageToWidget.dart`:
يتم تطبيق التحويلات بالترتيب:
1. **التدوير (Rotation):** باستخدام `Transform.rotate`.
2. **القلب (Flip):** باستخدام `Matrix4.scale(-1, 1)` للقلب الأفقي، أو `scale(1, -1)` للقلب العمودي.

```dart
// Apply Flips
if (image.flipH || image.flipV) {
  imageWidget = Transform(
    alignment: Alignment.center,
    transform: Matrix4.identity()
      ..scale(image.flipH ? -1.0 : 1.0, image.flipV ? -1.0 : 1.0),
    child: imageWidget,
  );
}
```

## 4. الخلاصة
هذا الحل "الهجين" يضمن:
1. أن يأخذ **إطار الصورة** الحجم الصحيح دائماً (عبر تبديل الأبعاد).
2. أن يظهر **محتوى الصورة** بالاتجاه الصحيح (عبر إلغاء دوران XML عندما يكون هناك تعارض محتمل مع EXIF).
