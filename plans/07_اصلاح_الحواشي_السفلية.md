# خطة 7: إصلاح الحواشي السفلية

## الوصف
إصلاح عدة مشاكل خطيرة في نظام الحواشي السفلية: حذف معظم محتوى الحواشي متعددة الفقرات، خطأ ترتيب الأرقام، الخط الفاصل، الأسطر الفارغة، والحفاظ على تنسيق الأرقام.

## الأولوية: عالية
## الوقت المتوقع: 8-10 ساعات

---

## ⛔ قواعد إلزامية قبل التنفيذ
1. **يجب الرجوع إلى** `WordXmlDoumentation/` (خاصة `extracted_reference.txt`) وقراءة أقسام `w:footnotes`، `w:footnoteReference`، `w:separator`، `w:continuationSeparator` قبل أي تعديل.
2. **ممنوع الحلول الترقيعية**: التعديل يجب أن يعمل على عشرات آلاف الكتب. الحاشية قد تحتوي على فقرة واحدة أو عشرين فقرة — يجب دعم الكل.
3. **ممنوع hardcode** لعدد فقرات أو أنماط خاصة بكتاب واحد.
4. **التوافق العكسي**: يجب التعامل مع الكاش القديم (FootNote بفقرة واحدة) دون كسر الكتب المحمّلة مسبقاً.
5. **الاختبار**: اختبار على 5 كتب مختلفة (كتب بحواشٍ طويلة وقصيرة، وكتب بدون حواشٍ).
6. **كود نظيف + مبدأ المسؤولية الواحدة (SRP)**: كل ملف/كلاس مسؤول عن شيء واحد فقط. أنشئ ملفات جديدة بدلاً من حشر الكود في ملف موجود. لا تكرر الكود (DRY). الدوال قصيرة وواضحة (40-50 سطراً كحد أقصى). اتبع أسلوب المشروع الحالي. لا تترك كوداً ميتاً أو معلّقاً.

---

## السياق التقني

### كيف تُحلَّل الحواشي حالياً
1. **DocFootNotes.dart** يقرأ `word/footnotes.xml` ويُنشئ كائنات `FootNote`
2. كل `FootNote` يحتوي على `Paragraph` واحدة فقط
3. **WordUtils.dart** (`addFnToPage()`) يربط الحواشي بالصفحات عبر `footNoteId`
4. **WordPage.dart** (`footnotesW()`) يعرض الحواشي أسفل الصفحة

### الخلل الجذري المكتشف
في `DocFootNotes.dart` سطر 26:
```dart
XmlElement xmlPar = fn.getElement("w:p")!;  // يأخذ أول فقرة فقط!
```
دالة `getElement("w:p")` تُرجع **أول** عنصر `<w:p>` فقط. إذا كانت الحاشية تحتوي على عدة فقرات، يُهمَل كل ما بعد الأولى. **هذا هو سبب حذف 3/4 من الحواشي.**

## الخطوات التفصيلية

### 1. إصلاح دعم الحواشي متعددة الفقرات (3 ساعات) — الأهم

#### 1.1 تعديل نموذج FootNote
```dart
// FootNote.dart — الحالي
class FootNote {
  Paragraph p;        // ← فقرة واحدة فقط!
  String id;
  String? displayNumber;
}
```
**التعديل المطلوب**:
```dart
class FootNote {
  List<Paragraph> paragraphs;  // ← قائمة فقرات
  String id;
  String? displayNumber;
  
  // للتوافق العكسي
  Paragraph get p => paragraphs.first;
}
```

#### 1.2 تعديل DocFootNotes.dart
```dart
// الحالي (خاطئ):
XmlElement xmlPar = fn.getElement("w:p")!;
Paragraph paragraph = Paragraph(wordPage).fromXml(xmlPar);
FootNote footNote = FootNote(paragraph, id);

// المطلوب (صحيح):
List<Paragraph> paragraphs = [];
for (var xmlPar in fn.findElements("w:p")) {
  Paragraph paragraph = Paragraph(wordPage).fromXml(xmlPar);
  paragraph.sectionType = 'footnote';
  paragraphs.add(paragraph);
}
FootNote footNote = FootNote(paragraphs, id);
```

#### 1.3 تعديل عرض الحواشي
- في `WordPage.footnotesW()`:
  - عرض جميع فقرات الحاشية وليس الأولى فقط
  ```dart
  ...fns.expand((fn) => fn.paragraphs.map((p) => 
    Padding(
      padding: const EdgeInsets.symmetric(horizontal: 16.0, vertical: 2.0),
      child: p.toWidget(),
    )
  )),
  ```

#### 1.4 تعديل الـ JSON serialization
- تحديث `FootNote.g.dart` (يُعاد توليده)
- تحديث `fromJson/toJson` و `fromMap` لدعم `List<Paragraph>`
- التعامل مع الكاش القديم (paragraph مفرد) للتوافق العكسي

#### 1.5 تعديل WordUtils.addFnToPage()
- تعديل ليعمل مع `paragraphs` بدلاً من `p` المفرد
- `updateDisplayNumber` يعمل على الفقرة الأولى فقط (صحيح)

---

### 2. إصلاح ترتيب أرقام الحواشي (2 ساعة)

#### 2.1 تحليل المشكلة
- "بعض أرقام الحواش يجعلها الملف في غير مكانها"
- السبب المحتمل: `addFnToPage()` في `WordUtils.dart` يعتمد على ترتيب ظهور `footNoteId` في الفقرات
- إذا كان ترتيب الـ runs غير صحيح، يتغير ترتيب الأرقام

#### 2.2 خطوات الإصلاح
1. **تتبع ترتيب الظهور**: التأكد من أن `footNoteId` يُلتقط بالترتيب الصحيح من XML
2. **مقارنة مع الأصل**: فحص ملف الوورد الأصلي للتأكد من تطابق الأرقام
3. **تصحيح الترقيم**: إذا كان الوورد يستخدم ترقيم مستمر (`continuous`) أو لكل صفحة (`restartEachPage`)

---

### 3. إصلاح الخط الفاصل بين المتن والحاشية (1.5 ساعة)

#### 3.1 السياق
في Word، يوجد خط فاصل أفقي بين نص الصفحة والحواشي السفلية. هذا الخط يُعرَّف في `word/footnotes.xml` كعنصر `<w:separator>` أو `<w:continuationSeparator>`.

#### 3.2 الحل
- في `WordPage.footnotesW()`:
  - إضافة خط فاصل (`Divider`) قبل الحواشي
  - الخط يكون مباشرة تحت آخر فقرة في المتن وفوق أرقام الحواشي
  ```dart
  if (fns.isNotEmpty) {
    return Column(
      children: [
        // الخط الفاصل
        Padding(
          padding: EdgeInsets.symmetric(horizontal: 16),
          child: Align(
            alignment: AlignmentDirectional.centerStart,
            child: SizedBox(
              width: 200, // عرض الخط (ثلث الصفحة تقريباً)
              child: Divider(thickness: 1, color: Colors.black),
            ),
          ),
        ),
        // الحواشي
        ...fns.map((fn) => ...),
      ],
    );
  }
  ```

---

### 4. إزالة الأسطر الفارغة بين الحواشي (0.5 ساعة)

#### 4.1 المشكلة
- يُضاف سطر فارغ بين كل حاشية وأخرى بخلاف الملف الأصلي

#### 4.2 الحل
- في `WordPage.footnotesW()`:
  - تقليل `vertical padding` بين الحواشي
  - حالياً: `padding: const EdgeInsets.symmetric(vertical: 2.0)` — قد يكون كافياً
  - فحص إذا كانت المشكلة من `Paragraph.toWidget()` الذي يضيف margin/padding إضافي
  - التحقق من وجود فقرات فارغة في البيانات المحللة

---

### 5. الحفاظ على تنسيق الأرقام (عربي/إنجليزي) (1 ساعة)

#### 5.1 المشكلة
- أحياناً الأرقام تظهر عربية وأحياناً إنجليزية بشكل عشوائي
- المطلوب: الحفاظ على التنسيق الأصلي من الملف

#### 5.2 السبب
في `WordUtils.dart` (`addFnToPage()` سطر 103-114):
```dart
if (isBodyArabic) {
  bodyNum = toArabicNumbers(bodyNum);
}
if (isFootnoteArabic || isBodyArabic) {
  footerNum = toArabicNumbers(footerNum);
}
```
المنطق يعتمد على **لغة النص المحيط** وليس على تنسيق الأرقام الأصلي في الملف.

#### 5.3 الحل
- قراءة تنسيق الأرقام من خصائص القسم (`<w:pgNumType w:fmt="...">`)
- أو من خصائص الحاشية نفسها
- أو من لغة النص (`w:lang` في `rPr`)
- استخدام التنسيق الأصلي بدلاً من التخمين بناءً على محتوى النص
