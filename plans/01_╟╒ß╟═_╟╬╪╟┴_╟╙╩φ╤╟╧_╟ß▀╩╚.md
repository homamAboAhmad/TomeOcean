## الوصف
إصلاح ثلاث مشاكل متعلقة بعملية استيراد الكتب: خطأ الملف الموجود مسبقاً، تكرار إضافة الكتب، والتنبيه عند وجود ملف مفتوح.

## الأولوية: عالية
## الوقت المتوقع: 6-8 ساعات

- **كود نظيف + مبدأ المسؤولية الواحدة (SRP)**: كل ملف/كلاس مسؤول عن شيء واحد فقط. أنشئ ملفات جديدة بدلاً من حشر الكود في ملف موجود. لا تكرر الكود (DRY). الدوال قصيرة وواضحة (40-50 سطراً كحد أقصى). اتبع أسلوب المشروع الحالي. لا تترك كوداً ميتاً أو معلّقاً.

## المشكلة الأولى: خطأ PathExistsException

### الوصف
عند استيراد أي ملف يظهر الخطأ:
```
PathExistsException: Cannot copy file to 'C:\Users\_\Documents\المكتبة\_temp_...' 
path = '...' (OS Error: Cannot create a file when that file already exists, errno = 183)
```

### السبب الجذري
في ملف `BookProcessingService.dart` السطر 357، الدالة `File(finalBookPath).copy(tempFilePath)` تفشل إذا كان الملف المؤقت `_temp_` موجوداً مسبقاً (من عملية سابقة لم تُنظَّف بشكل صحيح).

### خطوات الإصلاح
1. **فحص ملف `BookProcessingService.dart`** (سطر 354-362):
   - قبل نسخ الملف، تحقق من وجود الملف المؤقت واحذفه إن وجد
   - أضف `try/catch` مع منطق إعادة المحاولة
2. **إضافة تنظيف شامل** عند بداية عملية المعالجة:
   - حذف أي ملفات `_temp_*` متبقية من عمليات سابقة
3. **إصلاح منطق الإلغاء**:
   - التأكد من حذف الملفات المؤقتة عند إلغاء العملية (السطور 369-373 موجود لكنه قد لا يعمل في كل الحالات)

### الكود المقترح
```dart
// قبل النسخ - حذف المؤقت إن وجد
try {
  if (File(tempFilePath).existsSync()) {
    await File(tempFilePath).delete();
  }
  await File(finalBookPath).copy(tempFilePath);
} catch (e) {
  // ...
}
```

## المشكلة الثانية: إضافة الكتب مرتين (مع temp)

### الوصف
أحياناً يظهر الكتاب مرتين في المكتبة: مرة باسم `_temp_اسم_الكتاب` ومرة بالاسم الأصلي.

### السبب المحتمل
- الملف المؤقت لم يُحذف بعد انتهاء المعالجة
- أو أن الكاش يُنشأ باسم الملف المؤقت بدلاً من الأصلي
- في `_parseAndCacheBookInternal` (سطر 535) يُستخدم `titleOverride` لتجاوز هذا لكن قد يكون هناك حالات لا يعمل فيها

### خطوات الإصلاح
1. **فحص عملية التنظيف بعد المعالجة** (السطور 390-395):
   - التأكد من حذف الملف المؤقت في جميع المسارات (نجاح/فشل/إلغاء)
2. **إضافة تحقق في واجهة قائمة الكتب**:
   - تصفية الكتب التي تبدأ بـ `_temp_` من العرض
3. **إضافة تنظيف عند بدء التطبيق**:
   - حذف أي ملفات `_temp_*` من مجلد المكتبة عند الإطلاق
4. **مراجعة دالة تحميل قائمة الكتب**:
   - التأكد من عدم إدراج ملفات `_temp_` في القائمة

## المشكلة الثالثة: تنبيه عند وجود ملف وورد مفتوح خارج التطبيق

### الوصف
عند إضافة كتاب جديد، التطبيق يُغلق ملفات الوورد المفتوحة حالياً على الجهاز (لأن `pageRender.exe` يستخدم Word COM automation). هذا يؤدي إلى فقدان عمل المستخدم غير المحفوظ في Microsoft Word.

### السبب الجذري
في `BookProcessingService.dart`، مرحلة `rendering` تستدعي `pageRender.exe` الذي يفتح Word عبر COM. هذا قد يتفاعل مع نسخة Word المفتوحة حالياً، أو يغلقها عند انتهاء العملية (`word.Quit()`).

### خطوات الإصلاح
1. **كشف ملفات Word المفتوحة قبل بدء المعالجة**:
   - قبل استدعاء `pageRender.exe`، فحص ما إذا كان `WINWORD.EXE` يعمل حالياً:
     ```dart
     // استخدام Process لفحص العمليات الجارية
     ProcessResult result = await Process.run('tasklist', ['/FI', 'IMAGENAME eq WINWORD.EXE', '/NH']);
     bool wordIsRunning = !result.stdout.toString().contains('No tasks');
     ```
2. **عرض تنبيه إذا كان Word مفتوحاً**:
   - إظهر رسالة: "يوجد ملف وورد مفتوح حالياً على الجهاز. إضافة الكتاب قد تتطلب إغلاقه. هل تريد المتابعة؟ يُرجى حفظ عملك أولاً."
   - خيارات: **حفظ ومتابعة** (ينتظر المستخدم يحفظ ثم يضغط متابعة) / **إلغاء**
3. **تحسين pageRender.exe**:
   - تعديل السكريبت بحيث يستخدم نسخة Word جديدة معزولة بدلاً من الاتصال بالنسخة الموجودة
   - أو: استخدام `word = win32com.client.DispatchEx("Word.Application")` بدلاً من `Dispatch` لإنشاء نسخة مستقلة
   - عدم استدعاء `word.Quit()` إذا كانت نسخة Word موجودة مسبقاً
4. **الملفات المعنية**:
   - `lib/Services/BookProcessingService.dart` — فحص Word قبل بدء المعالجة
   - `lib/UI/HomePage.dart` أو `HomePageBookManagement.dart` — عرض التنبيه
   - `scripts/pageRender.py` — تحسين إدارة Word COM لعزل النسخة
