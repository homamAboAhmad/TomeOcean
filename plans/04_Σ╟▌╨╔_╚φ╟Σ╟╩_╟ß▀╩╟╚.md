# خطة 4: نافذة بيانات الكتاب عند الإضافة

## الوصف
إضافة نافذة إجبارية تظهر عند استيراد أي كتاب جديد، يُدخل فيها المستخدم بيانات الكتاب (اسم المؤلف، تاريخ الوفاة، التصنيف، إلخ) قبل بدء المعالجة.

## الأولوية: متوسطة
## الوقت المتوقع: 6-8 ساعات

---

## ⛔ قواعد إلزامية قبل التنفيذ
> **اقرأ `plans/00_فهرس_الخطط.md` أولاً للاطلاع على جميع القواعد العامة.**

- **كود نظيف + مبدأ المسؤولية الواحدة (SRP)**: كل ملف/كلاس مسؤول عن شيء واحد فقط. أنشئ ملفات جديدة بدلاً من حشر الكود في ملف موجود. لا تكرر الكود (DRY). الدوال قصيرة وواضحة (40-50 سطراً كحد أقصى). اتبع أسلوب المشروع الحالي. لا تترك كوداً ميتاً أو معلّقاً.

---

## السياق التقني
حالياً يوجد نظام بطاقة الكتاب `BookCard` في `lib/Models/BookCard.dart` و`lib/Dialogs/BookCard/book_card_dialog.dart` لكنه يُستخدم بعد إضافة الكتاب وليس قبله. كذلك يوجد نظام تصنيف بالمؤلفين (`Author`) والأقسام (`Section`) في `lib/Models/`.

البيانات المطلوبة عند الإضافة:
- اسم المؤلف
- تاريخ وفاة المؤلف (هجري/ميلادي)
- التصنيف (القسم)
- عنوان الكتاب (مع إمكانية تعديله)
- ملاحظات إضافية (اختياري)

---

## الخطوات التفصيلية

### 1. تصميم نافذة إدخال البيانات (3 ساعات)

#### 1.1 إنشاء الحوار
- إنشاء ملف `lib/UI/dialogs/book_metadata_input_dialog.dart`
- التصميم:
  ```
  ┌─────────────────────────────────────┐
  │        بيانات الكتاب الجديد          │
  ├─────────────────────────────────────┤
  │ عنوان الكتاب: [___________________] │
  │ اسم المؤلف:  [___________________] │
  │               (قائمة اقتراحات)       │
  │ تاريخ الوفاة: [______] هـ           │
  │ التصنيف:     [v اختر التصنيف    v]  │
  │ ملاحظات:     [___________________] │
  ├─────────────────────────────────────┤
  │         [إلغاء]    [متابعة]          │
  └─────────────────────────────────────┘
  ```

#### 1.2 حقل المؤلف مع الاقتراحات
- استخدام `Autocomplete` أو قائمة منسدلة تصفية
- عرض المؤلفين الموجودين مسبقاً في قاعدة البيانات
- إمكانية إضافة مؤلف جديد مباشرة
- مصدر البيانات: `BooksMetadataDatabase` الموجود

#### 1.3 حقل التصنيف
- قائمة منسدلة بالتصنيفات الموجودة
- إمكانية إضافة تصنيف جديد
- مصدر البيانات: `Section` model الموجود

#### 1.4 استخراج بيانات أولية من الملف
- محاولة استخراج العنوان من اسم الملف (بدون الامتداد)
- محاولة استخراج اسم المؤلف من `docProps/core.xml` (حقل `dc:creator`)
- ملء الحقول تلقائياً بالبيانات المستخرجة مع إمكانية التعديل

### 2. ربط النافذة بمسار الاستيراد (2 ساعة)

#### 2.1 تعديل مسار الاستيراد الفردي
- في `lib/UI/HomePage.dart` أو `HomePageBookManagement.dart`:
  - بعد اختيار الملف وقبل بدء المعالجة
  - عرض `BookMetadataInputDialog`
  - تمرير البيانات المُدخلة إلى `BookProcessingService`

#### 2.2 تعديل مسار الاستيراد الدفعي
- في `batch_file_processing_dialog.dart`:
  - عرض نافذة البيانات لكل ملف قبل بدء الدفعة
  - أو: عرض جدول يملأه المستخدم لجميع الملفات دفعة واحدة
  - خيار "تطبيق نفس المؤلف/التصنيف على الكل"

### 3. حفظ البيانات (2 ساعة)

#### 3.1 تعديل BookCard
- التأكد من أن `BookCard` يحتوي على جميع الحقول المطلوبة
- حفظ البيانات في `BookCardStorage` فوراً عند الإدخال

#### 3.2 تعديل BookProcessingService
- تمرير كائن `BookCard` مع بيانات الكتاب إلى `processBook()`
- حفظ البيانات في metadata.json عند الكاش
- فهرسة البيانات الوصفية في قاعدة بيانات البحث

### 4. معالجة حالة الاستيراد الدفعي (1 ساعة)
- تصميم واجهة جدولية لإدخال بيانات عدة كتب:
  ```
  ┌──────────────────────────────────────────────────┐
  │ الكتاب          │ المؤلف        │ التصنيف        │
  ├──────────────────────────────────────────────────┤
  │ كتاب 1         │ [_________]   │ [v______v]     │
  │ كتاب 2         │ [_________]   │ [v______v]     │
  │ كتاب 3         │ [_________]   │ [v______v]     │
  ├──────────────────────────────────────────────────┤
  │ [تطبيق على الكل: المؤلف [___] التصنيف [v__v]]  │
  └──────────────────────────────────────────────────┘
  ```
