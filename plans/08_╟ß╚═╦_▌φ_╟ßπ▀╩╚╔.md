# خطة 8: إصلاح البحث في المكتبة وواجهة على نمط الشاملة

## الوصف
إصلاح مشكلة عدم فتح الملف عند الضغط على نتيجة البحث، وإعادة تصميم واجهة البحث لتشبه نظام الشاملة (نتائج أسفل + عرض النص أعلى).

## الأولوية: عالية
## الوقت المتوقع: 8-10 ساعات
## ✅ تم التوضيح: نعم، تقسيم أفقي (نتائج أسفل + نص أعلى) في نفس الشاشة.

---

## ⛔ قواعد إلزامية قبل التنفيذ
> **اقرأ `plans/00_فهرس_الخطط.md` أولاً للاطلاع على جميع القواعد العامة.**

- **كود نظيف + مبدأ المسؤولية الواحدة (SRP)**: كل ملف/كلاس مسؤول عن شيء واحد فقط. أنشئ ملفات جديدة بدلاً من حشر الكود في ملف موجود. لا تكرر الكود (DRY). الدوال قصيرة وواضحة (40-50 سطراً كحد أقصى). اتبع أسلوب المشروع الحالي. لا تترك كوداً ميتاً أو معلّقاً.

---

## السياق التقني

### المشكلة الأولى: نتائج البحث لا تفتح الملف
مسار التنقل الحالي:
1. `SearchResultsTabViewer.onResultTapped(bookPath, pageNumber)` (سطر 131)
2. → `HomePage._onBookSelected(File(bookPath), pageNumber: pageNumber)` (سطر 98)
3. → يحاول فتح الكتاب والانتقال للصفحة

**الأسباب المحتملة للفشل:**
- `bookPath` في نتائج البحث لا يتطابق مع المسار الفعلي للملف
- الكتاب لم يُحمَّل بعد من الكاش والفتح يفشل بصمت
- `pageNumber` في نتائج البحث هو index (يبدأ من 0) بينما الانتقال يتوقع رقم صفحة (يبدأ من 1)
- الملف غير موجود في المسار المخزن (مثلاً تم نقله)

### الواجهة الحالية
- نتائج البحث تظهر في تبويب منفصل (`SearchResultsTabViewer`)
- أو في لوحة أسفل نافذة البحث (`SearchResultsView` بارتفاع 300px)

## الخطوات التفصيلية

### المرحلة 1: إصلاح التنقل لنتائج البحث (3 ساعات)

#### 1.1 تشخيص المشكلة
1. إضافة logging مفصل في مسار التنقل:
   ```dart
   // في HomePage._handleSearchResultNavigation
   debugPrint("🔍 Search nav: bookPath=$bookPath, page=$pageNumber");
   ```
2. التحقق من:
   - هل `bookPath` موجود فعلاً؟
   - هل الكاش موجود لهذا الكتاب؟
   - هل `pageNumber` ضمن نطاق صفحات الكتاب؟

#### 1.2 إصلاح مطابقة المسار
- التأكد من أن `book_path` في نتائج البحث يطابق المسار في المكتبة
- تطبيع المسارات (backslash vs forward slash, case sensitivity)
- إضافة fallback: البحث بالاسم إذا فشل المسار

#### 1.3 إصلاح تحميل الكتاب
- إذا الكتاب غير مفتوح: فتحه من الكاش
- إذا الكاش غير موجود: إعادة معالجة الكتاب
- بعد الفتح: الانتقال للصفحة المطلوبة
- التأكد من أن `_jumpToPage()` يُنفَّذ بعد اكتمال التحميل (وليس قبله)

#### 1.4 إصلاح ترقيم الصفحات في البحث
- التأكد من أن `page_number` في نتائج البحث هو index صفحة (0-based)
- مقارنة مع `_jumpToPage()` الذي يتوقع 0-based index

### المرحلة 2: واجهة البحث على نمط الشاملة (5-7 ساعات)

#### 2.1 التصميم المقترح
```
┌────────────────────────────────────────────────┐
│                 شريط العنوان                     │
├────────────────────────────────────────────────┤
│                                                │
│         عرض نص الصفحة (النصف العلوي)            │
│         يعرض الصفحة التي ضُغط عليها            │
│         مع تمييز كلمات البحث                    │
│                                                │
├────────────────────────────────────────────────┤
│ ┌──────────────────────────────────────────┐   │
│ │ النتائج (النصف السفلي)                   │   │
│ │ ┌─────┬──────────────────────────────┐   │   │
│ │ │ ص 44│ نص النتيجة مع تمييز البحث   │   │   │
│ │ ├─────┼──────────────────────────────┤   │   │
│ │ │ ص 78│ نص النتيجة مع تمييز البحث   │   │   │
│ │ └─────┴──────────────────────────────┘   │   │
│ └──────────────────────────────────────────┘   │
├────────────────────────────────────────────────┤
│ شريط البحث: [___________] [بحث] [خيارات]      │
└────────────────────────────────────────────────┘
```

#### 2.2 إنشاء واجهة البحث الجديدة
- إنشاء `lib/UI/Search/shamela_style_search_view.dart`
- المكونات:
  1. **القسم العلوي**: عرض محتوى الصفحة (WordPageScreen مصغر)
  2. **القسم السفلي**: قائمة النتائج (مشابه للحالي)
  3. **شريط بحث سفلي**: حقل البحث + أزرار

#### 2.3 عرض الصفحة عند الضغط على نتيجة
- عند الضغط على نتيجة:
  1. تحميل صفحة الكتاب من الكاش
  2. عرضها في القسم العلوي
  3. تمييز كلمات البحث في النص
  - لا يُفتح تبويب جديد — يُعرض في نفس المكان

#### 2.4 خيار الانتقال للكتاب
- زر "فتح في تبويب جديد" يفتح الكتاب كاملاً في تبويب منفصل
- الضغط المزدوج على نتيجة = فتح الكتاب في تبويب

#### 2.5 إمكانية تقسيم الشاشة (Splitter)
- استخدام `Divider` قابل للسحب لتغيير نسبة التقسيم
- أو استخدام حزمة مثل `multi_split_view`
