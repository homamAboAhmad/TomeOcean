# خطة 14: إصلاح تنسيق النصوص

## الوصف
إصلاح مشاكل تنسيق النصوص: حجم النص المتغير عشوائياً، أقواس النص القرآني، الحفاظ على تنسيق الأرقام (عربي/إنجليزي)، ولون النص/الخلفية في مربعات النص.

## الأولوية: متوسطة
## الوقت المتوقع: 6-8 ساعات

---

## ⛔ قواعد إلزامية قبل التنفيذ
1. **يجب الرجوع إلى** `WordXmlDoumentation/` وقراءة أقسام `w:rPr` (خصائص النص)، `w:sz` (حجم الخط)، `w:color`، `w:shd`، `w:rFonts`، `w:lang`، و `w:rStyle` قبل أي تعديل.
2. **ممنوع الحلول الترقيعية**: التعديل يجب أن يتبع مواصفات Word XML بدقة ويعمل على عشرات آلاف الكتب.
3. **ممنوع hardcode** لأحجام خطوط أو ألوان خاصة بكتاب واحد.
4. **وراثة الأنماط**: يجب اتباع سلسلة وراثة التنسيق الصحيحة في Word: (مستوى المستند → النمط الأب → النمط المباشر → التنسيق المباشر على النص).
5. **الاختبار**: اختبار على 5 كتب مختلفة على الأقل.
6. **كود نظيف + مبدأ المسؤولية الواحدة (SRP)**: كل ملف/كلاس مسؤول عن شيء واحد فقط. أنشئ ملفات جديدة بدلاً من حشر الكود في ملف موجود. لا تكرر الكود (DRY). الدوال قصيرة وواضحة (40-50 سطراً كحد أقصى). اتبع أسلوب المشروع الحالي. لا تترك كوداً ميتاً أو معلّقاً.

---

## السياق التقني

### المشاكل المُبلَّغ عنها
1. **السيرة الفرنسية ص 15-47 وص 58+**: حجم النص صغير جداً بينما هو في الأصل أكبر
2. **السيرة الفرنسية**: أقواس النص القرآني ليست هي المستعملة في الأصل
3. **حوار هادئ**: لون خلفية مربع النص أسود بدل أزرق (الرقم أبيض فلا يظهر)
4. **عموماً**: الأرقام أحياناً عربية وأحياناً إنجليزية بشكل عشوائي

### ملفات التنسيق الرئيسية
- `lib/wordToHTML/RPr.dart` — خصائص النص (حجم، لون، خط، bold, italic)
- `lib/wordToHTML/PPr.dart` — خصائص الفقرة (محاذاة، تباعد، مسافات)
- `lib/wordToHTML/DocumentStyles.dart` — وراثة الأنماط
- `lib/wordToHTML/runT.dart` — تمثيل جزء النص (run)

## الخطوات التفصيلية

### 1. إصلاح حجم النص المتغير (3 ساعات)

#### 1.1 تشخيص السبب
المشكلة: في بعض الصفحات حجم النص يصبح صغيراً جداً ثم يعود لحجمه الطبيعي.

**الأسباب المحتملة**:
- **وراثة الأنماط خاطئة**: النمط (style) يحدد حجماً معيناً لكن الكود لا يقرأه بشكل صحيح
- **النمط الافتراضي**: عند غياب `w:sz` في `rPr`، يجب الرجوع إلى:
  1. نمط الفقرة `pStyle` → `rPr` → `sz`
  2. نمط المستند الافتراضي `docDefaults` → `rPrDefault` → `sz`
  3. ثم القيمة الافتراضية 10pt (20 half-points)
- **قسم جديد (sectPr)**: بعض الأقسام قد تُغيّر النمط الافتراضي

#### 1.2 فحص سلسلة الوراثة
**الملف**: `lib/wordToHTML/RPr.dart`

خطوات التحقق:
1. عند تحليل `w:rPr`: إذا `w:sz` غير موجود:
   - البحث في `w:rStyle` → الحصول على النمط → `rPr` → `sz`
   - البحث في `pStyle` الأب → `rPr` → `sz`
   - البحث في `docDefaults` → `rPrDefault` → `sz`
2. التأكد من أن `w:szCs` (حجم الخط للنص المعقد/العربي) يُقرأ بشكل صحيح

#### 1.3 تتبع المشكلة
```dart
// إضافة logging مؤقت في RPr.fromXml():
if (fontSize != null && fontSize! < 16) {  // أقل من 8pt
  debugPrint('⚠️ حجم خط صغير جداً: $fontSize (${fontSize!/2}pt) '
      'style=$styleName page=$pageNum');
}
```

#### 1.4 إصلاح الوراثة
**الملف**: `lib/wordToHTML/DocumentStyles.dart`

```dart
/// الحصول على حجم الخط الفعلي بعد وراثة الأنماط
double? getEffectiveFontSize(RPr? directRPr, String? rStyle, String? pStyle, WordDocument doc) {
  // الأولوية 1: تنسيق مباشر
  if (directRPr?.fontSize != null) return directRPr!.fontSize;
  
  // الأولوية 2: نمط النص (rStyle)
  if (rStyle != null) {
    XmlElement? style = getDocumentStyle(rStyle, doc);
    double? sz = _getSzFromStyle(style);
    if (sz != null) return sz;
  }
  
  // الأولوية 3: نمط الفقرة (pStyle) → rPr
  if (pStyle != null) {
    XmlElement? style = getDocumentStyle(pStyle, doc);
    double? sz = _getSzFromStyle(style);
    if (sz != null) return sz;
    
    // الأولوية 3.5: النمط الأب (basedOn)
    String? basedOn = style?.getElement('w:basedOn')?.getAttribute('w:val');
    if (basedOn != null) {
      XmlElement? parentStyle = getDocumentStyle(basedOn, doc);
      sz = _getSzFromStyle(parentStyle);
      if (sz != null) return sz;
    }
  }
  
  // الأولوية 4: الافتراضي
  return doc.defaultRPr?.fontSize;
}

double? _getSzFromStyle(XmlElement? style) {
  var rPr = style?.getElement('w:rPr');
  String? szCs = rPr?.getElement('w:szCs')?.getAttribute('w:val');
  String? sz = rPr?.getElement('w:sz')?.getAttribute('w:val');
  // تفضيل szCs للنص العربي
  return double.tryParse(szCs ?? sz ?? '');
}
```

### 2. إصلاح أقواس النص القرآني (1.5 ساعة)

#### 2.1 تحليل المشكلة
الأقواس القرآنية المزخرفة ﴿ ﴾ (U+FD3E, U+FD3F) قد تتحول إلى أقواس عادية ( ) أو { } عند العرض.

**الأسباب المحتملة**:
- الخط المستخدم لا يحتوي الأحرف القرآنية
- استبدال الأحرف أثناء التحليل

#### 2.2 الحل
- **لا نستبدل الأقواس يدوياً** (ترقيعي)
- نتأكد من أن:
  1. النص يُقرأ كما هو من XML دون تحويل أحرف
  2. الخط المستخدم يدعم الأحرف (مرتبط بخطة 12 — استخراج الخطوط)
  3. `w:rFonts` يُطبَّق بشكل صحيح على كل run

### 3. إصلاح لون النص والخلفية (1.5 ساعة)

#### 3.1 مشكلة "حوار هادئ"
التطبيق جعل لون خلفية مربع النص أسود بدلاً من أزرق.

#### 3.2 فحص قراءة الألوان
**الملف**: `lib/wordToHTML/RPr.dart` و `lib/Utils/ImageParser.dart`

- التأكد من قراءة `w:color` (لون النص):
  ```xml
  <w:color w:val="FFFFFF"/>  <!-- أبيض -->
  ```
- التأكد من قراءة `w:shd` (خلفية):
  ```xml
  <w:shd w:val="clear" w:color="auto" w:fill="0000FF"/>  <!-- أزرق -->
  ```
- التأكد من قراءة خلفية مربع النص (TextBox):
  ```xml
  <!-- في v:shape أو wsp -->
  <a:solidFill>
    <a:srgbClr val="0000FF"/>  <!-- أزرق -->
  </a:solidFill>
  ```

#### 3.3 الإصلاح
- تتبع مسار قراءة لون الخلفية في `ImageParser.parseTextBox()`:
  - التحقق من أنه يقرأ `a:solidFill` / `v:fill` / `w:shd` بشكل صحيح
  - التحقق من عدم وجود fallback إلى اللون الأسود عند فشل القراءة
- إصلاح القيمة الافتراضية: إذا لم يُقرأ لون → شفاف (`transparent`) وليس أسود

### 4. الحفاظ على تنسيق الأرقام (1 ساعة)

#### 4.1 المشكلة
الأرقام تتحول أحياناً من عربية (١٢٣) إلى إنجليزية (123) أو العكس.

#### 4.2 الحل الجذري
- **لا نحوّل الأرقام إطلاقاً** — نعرضها كما هي في XML
- إزالة أي استدعاءات `toArabicNumbers()` أو `toEnglishNumbers()` على نص المستند
- هذه الدوال يجب أن تُستخدم فقط في واجهة التطبيق (أرقام الصفحات في شريط الأدوات مثلاً) وليس في محتوى الكتاب
- فحص `lib/Utils/WordUtils.dart` و `lib/wordToHTML/runT.dart` لإزالة التحويلات غير الضرورية
