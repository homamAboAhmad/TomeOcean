# خطة: تقسيم الحواشي الطويلة عبر الصفحات (مطابقة الوورد)

## وصف المشكلة

عندما تكون الحاشية السفلية طويلة جداً (تملأ صفحتين أو أكثر)، يقسمها الوورد تلقائياً:
- يعرض الجزء الذي يسع في الصفحة الأولى
- يكمل الحاشية في أسفل الصفحة(الصفحات) التالية

**التطبيق حالياً** يعرض الحاشية كاملة في الصفحة الأولى التي تحتوي على المرجع،
مما يجعل الصفحة مكتظة وتظهر صفحات فارغة بعدها.

---

## تحليل السبب الجذري

### آلية العمل الحالية (مبسطة):

```
1. Python (pageRender.py):
   - يفتح الملف بالوورد، يضبط الصفحات (Repaginate)
   - يحقن Bookmarks (ShamelaPage_X) في document.xml فقط
   - يحقن {{PG:X}} markers بناءً على مواقع الـ Bookmarks
   ⚠️ لا يتعامل مع footnotes.xml إطلاقاً

2. Dart (WordUtils.addFnToPage):
   - لكل فقرة في الصفحة، يبحث عن مراجع حواشي (footnoteReference)
   - يجلب الحاشية كاملة (جميع فقراتها) من docFootNotes
   - يضيفها إلى wordPage.fns
   ⚠️ لا يوجد أي منطق لتقسيم أو توزيع الحاشية عبر الصفحات
```

### لماذا لا يمكن حل هذا من Dart وحدها؟

- تقسيم الحواشي في الوورد يعتمد على **محرك التخطيط الداخلي** (Layout Engine)
- محرك الوورد يحسب المساحة المتاحة في أسفل كل صفحة بالضبط
- يأخذ بالاعتبار: حجم الخط، تباعد الأسطر، هوامش الحاشية، ارتفاع الخط الفاصل
- لا تُخزن هذه المعلومات في XML — تُحسب ديناميكياً عند فتح الملف
- **محاولة إعادة حسابها في Dart ستكون حلاً ترقيعياً** (تقريبي وغير دقيق)

## الحل المقترح: حقن Bookmarks في الحواشي عبر Word COM

### الفكرة الأساسية

بما أن Word COM يعرف بالضبط أين تنتهي كل صفحة (حتى داخل الحواشي)،
سنستفيد من `Selection.GoTo` للانتقال إلى بداية كل صفحة والتحقق مما إذا كان
المؤشر داخل حاشية سفلية. إذا كان كذلك، نحقن Bookmark هناك.

### مراحل التنفيذ

### المرحلة 1: تعديل سكربت Python (`pageRender.py`)

#### الخطوة 1.1: تعديل `repaginate_and_save` لحقن Bookmarks في الحواشي

**الملف:** `scripts/pageRender.py`
**الدالة:** `repaginate_and_save(docx_path)`

**المنطق الحالي** (سطر ~105):
```python
for p in range(1, total_pages + 1):
    word_app.Selection.GoTo(1, 1, p)  # GoTo page p
    doc.Bookmarks.Add(Name=f"ShamelaPage_{p}", Range=word_app.Selection.Range)
```

**المنطق الجديد** (إضافة):
```python
for p in range(1, total_pages + 1):
    word_app.Selection.GoTo(1, 1, p)  # GoTo page p
    rng = word_app.Selection.Range

    # حقن Bookmark عادي في المتن
    doc.Bookmarks.Add(Name=f"ShamelaPage_{p}", Range=rng)

    # التحقق: هل المؤشر داخل حاشية سفلية؟
    # StoryType: wdFootnotesStory = 2
    story_type = rng.StoryType
    if story_type == 2:  # wdFootnotesStory
        # نحن داخل حاشية سفلية في هذه الصفحة
        # نحقن Bookmark خاص بالحاشية
        doc.Bookmarks.Add(Name=f"ShamelaFnPage_{p}", Range=rng)
        print(f"STATUS:Footnote bookmark injected at page {p}", flush=True)
```

> [!IMPORTANT]
> **تحقق مطلوب**: يجب التأكد أن `Selection.GoTo` ينقل المؤشر فعلاً إلى داخل
> الحاشية عندما تكون الحاشية ممتدة عبر الصفحة. إذا لم يكن كذلك، نحتاج لطريقة
> بديلة (مثل `StoryRanges` أو فحص كل `Footnote.Range`).

#### الخطوة 1.2: تعديل `process_xml_with_page_breaks` لمعالجة الـ Bookmarks في `footnotes.xml`

**الملف:** `scripts/pageRender.py`
**الدالة:** `process_xml_with_page_breaks(docx_path, output_path)`

**الإضافة:** بعد معالجة `document.xml`، نقرأ `footnotes.xml` ونبحث عن
الـ Bookmarks المحقونة (`ShamelaFnPage_X`) ونحقن `{{FN_PG:X}}` markers.

```python
# === معالجة footnotes.xml ===
fn_xml = os.path.join(extract_dir, 'word', 'footnotes.xml')
if os.path.exists(fn_xml):
    fn_tree = ET.parse(fn_xml)
    fn_root = fn_tree.getroot()

    # البحث عن bookmarks داخل الحواشي
    for footnote in fn_root.findall(f".//{{{NS['w']}}}footnote"):
        fn_id = footnote.get(f"{{{NS['w']}}}id")
        for para in footnote.findall(f".//{{{NS['w']}}}p"):
            bookmarks = para.findall(f".//{{{NS['w']}}}bookmarkStart")
            for bm in bookmarks:
                name = bm.attrib.get(f"{{{NS['w']}}}name", "")
                if name.startswith("ShamelaFnPage_"):
                    page_num = int(name.split("_")[2])
                    # حقن marker مخفي بعد الـ bookmark
                    marker = create_hidden_run_element(f"{{{{FN_PG:{page_num}:{fn_id}}}}}")
                    # إدراج بعد الـ bookmark
                    bm_parent = bm.getparent()
                    idx = list(bm_parent).index(bm)
                    bm_parent.insert(idx + 1, marker)

    fn_tree.write(fn_xml, encoding='UTF-8', xml_declaration=True)
```

#### الخطوة 2.3: تعديل `WordUtils.addFnToPage` لتوزيع الحواشي عبر الصفحات

**الملف:** `lib/Utils/WordUtils.dart`

```dart
void addFnToPage(WordPage wordPage) {
    // ... (المنطق الحالي)
    if (footNote != null) {
        // إذا كانت الحاشية مقسمة عبر صفحات
        if (footNote.pageBreaks.isNotEmpty) {
            // أضف فقط الفقرات الخاصة بهذه الصفحة
            int currentPageNum = wordPage.pageIndex;
            List<Paragraph> pageSpecificParagraphs =
                footNote.getPageParagraphs(currentPageNum);
            // أنشئ FootNote جزئي لهذه الصفحة
            FootNote partialFn = FootNote(pageSpecificParagraphs, footNote.id);
            partialFn.displayNumber = footNote.displayNumber;
            wordPage.fns.add(partialFn);
        } else {
            wordPage.fns.add(footNote);
        }
    }
}
```

#### الخطوة 2.4: تعامل مع الصفحات اللاحقة (حاشية مستمرة)

**الملف:** `lib/Utils/WordUtils.dart`
**الدالة:** `getPage()` أو `addParagraphToDocument()`

بعد بناء جميع الصفحات، نتحقق من وجود فقرات حاشية مخصصة للصفحات اللاحقة:

```dart
// بعد بناء جميع الصفحات:
for (var fnEntry in wordDocument.docFootNotes.entries) {
    FootNote fn = fnEntry.value;
    for (var pageBreak in fn.pageBreaks.entries) {
        int targetPage = pageBreak.key;
        // إذا كانت هذه الصفحة موجودة ولم تُضف إليها هذه الحاشية بعد
        if (targetPage <= pages.length) {
            WordPage targetWordPage = pages[targetPage - 1];
            // أنشئ FootNote جزئي وأضفه
            FootNote continuationFn = FootNote(pageBreak.value, fn.id);
            continuationFn.displayNumber = "(تابع)"; // أو استخدم نفس الرقم
            targetWordPage.fns.add(continuationFn);
        }
    }
}
```

## مراجعة المستخدم

> [!WARNING]
> ### نقطة حاسمة تحتاج تأكيد
> **هل `Selection.GoTo(1, 1, pageNum)` في Word COM يمكن أن ينقل المؤشر إلى داخل
> حاشية سفلية إذا كانت الحاشية تبدأ صفحة جديدة؟**
>
> يجب اختبار هذا يدوياً قبل البدء بالتنفيذ. الطريقة:
> 1. افتح كتاباً يحتوي على حاشية طويلة في الوورد
> 2. اضغط `Alt+F11` لفتح VBA
> 3. شغل الكود التالي في Immediate Window:
> ```vba
> Selection.GoTo 1, 1, [رقم الصفحة التي تبدأ فيها الحاشية المستمرة]
> Debug.Print Selection.StoryType  ' إذا كان = 2 فنحن داخل حاشية
> Debug.Print Selection.Range.Text
> ```
> إذا كان `StoryType = 2`، فالحل سيعمل. إذا لم يكن كذلك، نحتاج لطريقة بديلة.

> [!IMPORTANT]
> ### بديل محتمل إذا لم يعمل GoTo داخل الحواشي
> يمكن استخدام **مقاربة مختلفة**: بدلاً من الاعتماد على GoTo، يمكن لكل
> حاشية (`Footnote` object في Word COM) التحقق من عدد الصفحات التي تمتد عليها:
> ```vba
> For Each fn In doc.Footnotes
>     Dim fnRange As Range
>     Set fnRange = fn.Range
>     Dim startPage As Long
>     Dim endPage As Long
>     startPage = fnRange.Information(wdActiveEndPageNumber)
>     ' الانتقال لنهاية الحاشية
>     fnRange.Collapse wdCollapseEnd
>     endPage = fnRange.Information(wdActiveEndPageNumber)
>     If endPage > startPage Then
>         ' الحاشية ممتدة عبر عدة صفحات
>         Debug.Print "Footnote " & fn.Index & " spans pages " & startPage & " to " & endPage
>     End If
> Next fn
> ```
> هذا البديل أكثر موثوقية. يمكننا:
> 1. تحديد الحواشي الممتدة
> 2. إدراج bookmarks عند نقاط تقسيم الصفحات داخلها
>
> **لكن** هذا البديل أبطأ لأنه يتحقق من كل حاشية.

## مخطط التحقق

### 1. اختبار Word COM (يدوي - قبل البدء)
- فتح كتاب بحاشية طويلة
- تشغيل VBA snippet أعلاه
- تأكيد أن GoTo يدخل الحاشية أو استخدام البديل

### 2. اختبار السكربت Python (بعد التعديل)
```bash
python scripts/pageRender.py books_output path/to/book_with_long_footnote.docx --stage full
```
- التحقق من وجود `ShamelaFnPage_X` في `footnotes.xml` بعد المعالجة

### 3. اختبار التطبيق (بعد تعديل Dart)
- فتح الكتاب في التطبيق
- مقارنة عرض الحواشي مع الوورد صفحة بصفحة
- التأكد أن الصفحات التي كانت فارغة أصبحت تحتوي على تكملة الحاشية

### 4. اختبار التوافق العكسي
- فتح كتاب سابق (بدون markers الحواشي) — يجب أن يعمل بدون مشاكل
- فتح كتاب بحواشي قصيرة (عادية) — لا تأثير
