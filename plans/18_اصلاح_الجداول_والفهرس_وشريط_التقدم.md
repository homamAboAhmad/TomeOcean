# خطة 18: إصلاح الجداول والفهرس وشريط التقدم

## الوصف
إصلاح خمس مشاكل: تجاوز الجداول لحدود الصفحة (table overflow)، تراجع شريط التقدم عند استخراج الخطوط، رسائل إنجليزية في شريط التقدم، تدريجات الفهرس المتفاوتة، وتنقل الفهرس إلى آخر الصفحة بدلاً من أولها.

## الأولوية: عالية
## الحالة: ✅ مكتملة

## المشاكل والحلول

### 1. تجاوز الجداول (Table Overflow) — ✅

#### المشكلة
صفوف الجدول تتجاوز عرض الصفحة مما يسبب خطأ `RenderFlex overflow` في Flutter.

#### السبب الجذري
مشكلتان في `ParagraphTable.dart`:

**أ. عدم اتساق `totalGridTwips` مع `_getCellTwips`**:
عند غياب `w:tblGrid`، يتم حساب `totalGridTwips` من قيم `tcW` في الصف الأول. لكن إذا كانت `tcW` مفقودة لخلية ما:
- `totalGridTwips` يضيف `0` لتلك الخلية
- `_getCellTwips` يُعيد `1440` (بوصة واحدة كقيمة افتراضية)

هذا يجعل `scaleFactor = finalTableWidth / totalGridTwips` أكبر مما يجب، فتصبح عروض الخلايا أكبر من عرض الجدول.

**ب. غياب التطبيع لكل صف (per-row normalization)**:
`totalGridTwips` يُحسب من الصف الأول فقط. الصفوف الأخرى قد تحتوي على خلايا مختلفة (عدد، `gridSpan`، قيم `tcW`) مما يجعل مجموع عروضها يختلف عن عرض الجدول.

#### الملف: `lib/wordToHTML/ParagraphTable.dart`

#### الإصلاح

**1. توحيد القيمة الافتراضية** (السطر 66):
```dart
// قبل الإصلاح:
totalGridTwips += double.tryParse(w ?? '0') ?? 0;

// بعد الإصلاح — نفس القيمة الافتراضية المستخدمة في _getCellTwips:
double explicitW = double.tryParse(w ?? '0') ?? 0;
totalGridTwips += explicitW > 0 ? explicitW : 1440;
```

**2. تطبيع عرض كل صف** — إعادة هيكلة `getRowsWList` إلى ثلاث مراحل:
```
المرحلة 1: حساب عروض جميع الخلايا في الصف
المرحلة 2: إذا تجاوز المجموع عرض الجدول، يُقلَّص كل عرض بنسبة موحدة
المرحلة 3: بناء الودجات بالعروض المُصحَّحة
```

```dart
// Phase 2: Normalize
double totalRowWidth = cellWidths.fold(0.0, (sum, w) => sum + w);
if (totalRowWidth > finalTableWidth && totalRowWidth > 0) {
  double ratio = finalTableWidth / totalRowWidth;
  for (int i = 0; i < cellWidths.length; i++) {
    cellWidths[i] *= ratio;
  }
}
```

**3. شبكة أمان (Safety Net)**: إضافة `clipBehavior: Clip.hardEdge` على مستوى الجدول ككل لمنع أي تجاوز بصري متبقي.

#### لماذا هذا ليس حلاً ترقيعياً
- يعالج **السبب الجذري**: عدم اتساق حساب العروض بين `totalGridTwips` و `_getCellTwips`
- يعمل على **جميع أنواع الجداول**: مع أو بدون `tblGrid`، مع `vMerge`، مع `gridSpan`
- يتبع مبدأ Word: "الجدول يجب ألا يتجاوز عرض الصفحة"
- التطبيع النسبي يحافظ على التناسب بين الأعمدة

### 2. تراجع شريط التقدم (Progress Regression) — ✅

#### المشكلة
عند ظهور خطوة "استخراج الخطوط المدمجة"، يرجع شريط التقدم إلى الوراء (من 75% إلى 40%) ثم يكمل.

#### السبب الجذري
في `BookProcessingService.dart`، الكود الرئيسي يُرسل `progress = 0.75` قبل تشغيل الـ isolate. لكن الـ isolate يبدأ بإرسال `progress = 0.4` ثم `0.5` ثم `0.75` — أي يرجع بالتقدم للخلف.

#### الملف: `lib/Services/BookProcessingService.dart`

#### الإصلاح
إعادة تعيين قيم التقدم في الـ isolate لتكون تصاعدية بدءاً من `0.76`:

| المرحلة | قبل | بعد |
|---------|------|------|
| فك الضغط | 0.40 | 0.76 |
| استخراج الخطوط | 0.50 | 0.78 |
| قراءة الهيكل | 0.75 | 0.80 |
| التحليل (صفحة بصفحة) | 0.75–0.90 | 0.80–0.90 |
| الحفظ | 0.90–0.95 | 0.90–0.94 |

### 4. تدريجات الفهرس (TOC Indentation) — ✅

#### المشكلة
عناصر الفهرس (جدول المحتويات) تظهر بمسافات بادئة متفاوتة بناءً على مستوى TOC، بينما في Word تبدأ جميعها من نفس النقطة.

#### السبب الجذري
في `Paragraph.dart`، دالة `_buildTOCWidget` تستخدم مسافة بادئة ثابتة محسوبة من `tocLevel`:
```dart
double indent = ((pPr?.tocLevel ?? 1) - 1) * 24.0;
```
هذا يضيف مسافة اصطناعية غير موجودة في ملف Word الأصلي.

#### الملف: `lib/wordToHTML/Paragraph.dart`

#### الإصلاح
استبدال المسافة الثابتة بالمسافة الفعلية من خصائص الفقرة (`w:ind w:right`):
```dart
double indent = pPr?.paddingRight ?? 0;
```

### 5. تنقل الفهرس إلى آخر الصفحة — ✅

#### المشكلة
عند الضغط على عنصر في الفهرس الجانبي أو جدول المحتويات، يتم الانتقال إلى نهاية الصفحة بدلاً من بدايتها.

#### السبب الجذري
في `DocViewer.dart`، دالة `_jumpToPage` لم تأخذ في الاعتبار الـ padding العلوي (20px) لـ ListView:
```dart
// قبل — يبدأ من 0 بينما الصفحة الأولى تبدأ عند 20px:
double offset = pageIndex * ((pageHeight * zoom) + 20.0);
```

#### الملف: `lib/UI/DocViewer.dart`

#### الإصلاح
إضافة الـ padding العلوي إلى حساب الموضع:
```dart
double offset = 20.0 + (pageIndex * pageTotalHeight);
```
وتحديث مُعالج الـ scroll notification ليتوافق:
```dart
int newPageIndex = ((_scrollController.offset - 20.0) / pageTotalHeight).round();
```
